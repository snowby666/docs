title: 'Messages API'
openapi: 'POST /messages'
description: 'Create a message with the Anthropic Messages format'
---

Send a structured conversation to a model and receive an assistant message. Models trained for alternating turns expect `user` and `assistant` messages; a top-level `system` field sets standing instructions.

## Create a message

`POST /v1/messages`

### Headers

| Header | Required | Description |
|---|---|---|
| `Authorization` | Yes* | `Bearer <api_key>` |
| `x-api-key` | Yes* | Alternative to `Authorization` |
| `Content-Type` | Yes | `application/json` |
| `anthropic-version` | No | Accepted when present (for example `2023-06-01`) |

\*Provide one of `Authorization` or `x-api-key`.

### Body parameters

<ParamField body="model" type="string" required>
  Model ID. Examples: `claude-sonnet-4-5-20250929`, `kimi-k2.6:dev`.
</ParamField>

<ParamField body="messages" type="array" required>
  Input turns. Each item has `role` and `content`.

  - `role`: `user`, `assistant`, or `system` (mid-conversation system instruction; cannot be the first entry)
  - `content`: string, or an array of content blocks (see below)

  Consecutive same-role turns may be merged by the model. If the last message is `assistant`, generation continues from that partial reply.
</ParamField>

<ParamField body="max_tokens" type="integer">
  Maximum number of tokens to generate before stopping. Required by many Anthropic clients; omit only when the client supplies a default.
</ParamField>

<ParamField body="system" type="string | array">
  Standing system prompt for the whole conversation.

  - string: plain text
  - array: list of `{ "type": "text", "text": "...", "cache_control"?: { "type": "ephemeral", "ttl"?: "5m" \| "1h" } }` blocks

  Keep the array shape when using prompt caching breakpoints. Do not put the initial system prompt as `messages[0].role = "system"`; use this field instead.
</ParamField>

<ParamField body="thinking" type="object">
  Extended thinking configuration.

  | `type` | Fields |
  |---|---|
  | `enabled` | `budget_tokens` (required), optional `display` |
  | `adaptive` | optional `budget_tokens`, optional `display` |
  | `disabled` | none |

  `display` is `"summarized"` or `"omitted"`. When thinking is enabled, assistant `content` may include `thinking` blocks (with `signature`) before `text` / `tool_use`.
</ParamField>

<ParamField body="tools" type="array">
  Tools the model may call. Each custom tool:

  - `name` (string, required)
  - `description` (string)
  - `input_schema` (JSON Schema object)
  - optional: `cache_control`, `strict`, `defer_loading`, `eager_input_streaming`, `allowed_callers`, `input_examples`

  Anthropic built-in tools may set `type` (for example `bash_20250124`) and omit `input_schema`.
</ParamField>

<ParamField body="tool_choice" type="object">
  How the model should use tools:

  - `{ "type": "auto" }`
  - `{ "type": "any" }`
  - `{ "type": "tool", "name": "<tool_name>" }`
  - `{ "type": "none" }`
</ParamField>

<ParamField body="temperature" type="number">
  Sampling temperature. Range depends on the upstream model (commonly 0 to 1).
</ParamField>

<ParamField body="top_p" type="number">
  Nucleus sampling. `0` is ignored.
</ParamField>

<ParamField body="top_k" type="integer">
  Top-k sampling. `0` is ignored.
</ParamField>

<ParamField body="stop_sequences" type="array">
  Custom strings that stop generation when emitted.
</ParamField>

<ParamField body="stream" type="boolean">
  If `true`, respond with server-sent events. Default `false`.
</ParamField>

<ParamField body="metadata" type="object">
  Optional `{ "user_id": string }` for abuse tracking. Opaque ID only; do not put PII.
</ParamField>

<ParamField body="betas" type="array">
  Anthropic beta feature flags. Accepted and forwarded when relevant.
</ParamField>

<ParamField body="context_management" type="object">
  Server-side context edits, for example:

  ```json
  {
    "edits": [
      { "type": "clear_thinking_20251015", "keep": "all" }
    ]
  }
  ```
</ParamField>

<ParamField body="output_config" type="object">
  Output controls such as `{ "effort": "low" | "medium" | "high" }`.
</ParamField>

### Content blocks

`content` may be a string (shorthand for one `text` block) or an array of blocks.

#### User / mid-conversation system

| `type` | Fields | Notes |
|---|---|---|
| `text` | `text`, optional `cache_control` | Primary text |
| `image` | `source` | `source.type`: `base64` (`media_type`, `data`) or `url` (`url`) |
| `document` | `source`, optional `title`, `context` | PDF / text document input |
| `tool_result` | `tool_use_id`, `content`, optional `is_error`, `cache_control` | Reply to a prior `tool_use` |
| `mid_conv_system` | `content` (text blocks) | Structured mid-conversation system payload |
| `tool_addition` / `tool_removal` | `tool` | Mid-conversation tool availability changes |

Server tool result types (for example `web_search_tool_result`) are accepted as passthrough blocks.

#### Assistant

| `type` | Fields | Notes |
|---|---|---|
| `text` | `text`, optional `cache_control` | Visible reply |
| `tool_use` | `id`, `name`, `input`, optional `cache_control` | Client tool call |
| `server_tool_use` | `id`, `name`, `input` | Server-executed tool call |
| `thinking` | `thinking`, `signature` | Prior-turn reasoning; echo unchanged on the next request |
| `redacted_thinking` | `data` | Encrypted thinking; echo unchanged |

On multi-turn requests, include the full previous assistant `content` array (including thinking blocks) so reasoning continuity is preserved.

### Response

Non-streaming responses are Anthropic message objects:

```json
{
  "id": "msg_...",
  "type": "message",
  "role": "assistant",
  "model": "claude-sonnet-4-5-20250929",
  "content": [
    { "type": "text", "text": "..." }
  ],
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": {
    "input_tokens": 10,
    "output_tokens": 20
  }
}
```

`stop_reason` is typically `end_turn`, `max_tokens`, `stop_sequence`, or `tool_use`.

Errors use Anthropic's envelope:

```json
{
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "message": "..."
  }
}
```

### Example

<CodeGroup>

```bash cURL
curl https://api.electronhub.ai/v1/messages \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-5-20250929",
    "max_tokens": 1024,
    "messages": [
      {"role": "user", "content": "Hello"}
    ]
  }'
```

```python Python
import anthropic

client = anthropic.Anthropic(
    api_key="YOUR_API_KEY",
    base_url="https://api.electronhub.ai/v1",
)

message = client.messages.create(
    model="claude-sonnet-4-5-20250929",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Hello"}],
)
print(message.content)
```

```javascript Node.js
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  apiKey: "YOUR_API_KEY",
  baseURL: "https://api.electronhub.ai/v1",
});

const message = await client.messages.create({
  model: "claude-sonnet-4-5-20250929",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Hello" }],
});

console.log(message.content);
```

</CodeGroup>

## Count tokens

`POST /v1/messages/count_tokens`

Estimate input tokens for a Messages request without running inference.

### Body

Same shape as [Create a message](#create-a-message): at least `model` and `messages`. `system`, `tools`, and related fields are included in the estimate when present.

### Response

```json
{
  "input_tokens": 1234
}
```
